# BAWSALA security review: findings

- **Reviewer:** Agent E (independent security review)
- **Date:** 2026-11-02
- **Target:** production build at `http://localhost:3000`, using the local DB `bawsala_dev`
- **Method:** code review of `src/`, `db/migrations/` and the config. I checked behaviour with a Node `fetch` harness, using only accounts I created through `POST /api/v1/auth/signup`. I used `psql` only to look up object IDs, to confirm results and to clean up afterwards.
- **LLM:** `ANTHROPIC_API_KEY` is not set, so every chat ran on the deterministic "basic" engine. Any LLM-specific behaviour listed below is from code review only.
- **Not done:** no load or DoS testing, and no requests to any host other than localhost.
- **Cleanup:** I deleted all test users, including the bootstrap admin, and the two test institutions. A check afterwards found 0 left over. The `audit_log`, `events` and `rate_limits` rows written by the tests are still there.

Severity counts: **critical 0 · high 1 · medium 4 · low 9 · info 5**

| F-03 | **medium** | LLM10 unbounded consumption | `src/app/api/v1/chat/route.ts:28,33-35`; `src/server/repo/conversations.ts:75-78`; `src/server/ai/tools/index.ts:77-81`; `src/server/ai/usage.ts` | **The daily AI quota can be bypassed.** `messagesToday()` counts rows in `messages` with `role='user'` from the last 24 h. (2) Deleting a conversation cascades to its messages and resets the counter to 0. | F-04 | **medium** | DoS / input limits | `src/server/http/api.ts:26-27`; `src/app/api/v1/files/route.ts:16-18,22` | **The body-size check only looks at the `Content-Length` header.** A chunked request sends no `Content-Length`, so `req.json()` and `req.formData()` buffer the whole body, with no upper limit, before any validation. App Router route handlers have no default body limit. | A 300 KB JSON body to `POST /api/v1/try` with `Content-Length` returned `400 Body too large`. Also set `client_max_body_size` or the platform body limit at the reverse proxy. |
| F-05 | **medium** | File parsing | `src/server/repo/files.ts:34-37,41-51` | **(code review only) PDF and DOCX parsing runs inside the web process with no limit on decompressed size.** `mammoth` and JSZip inflate `word/document.xml` fully into memory, so a 5 MB DOCX zip bomb can expand to several GB. `unpdf`/pdf.js can also be made to do heavy CPU work. `withTimeout` uses `Promise.race`, so it stops the request from waiting but does not stop the parsing, which keeps running and holding memory. One authenticated user (20 uploads per hour) could crash the server process (OOM) for everyone. | Code path: `POST /api/v1/files` → `saveUpload` → `extractText` → `mammoth.extractRawText({buffer})`. ## Verified OK

- **Session cookie.** The `Set-Cookie` header is `bawsala_session=…; Path=/; Expires=+30d; Secure; HttpOnly; SameSite=lax`. The token is 32 random bytes, and only its SHA-256 is stored (`tokens.ts`, `session.ts:23`).
- **Session revocation.** After signout, the old cookie gets `401` on `/api/v1/me`. When an admin changes a user's role, that user's old session gets `401`, because all their sessions are deleted (`admin/users/[id]/route.ts:21`).
- **Signin responses do not reveal accounts.** An unknown email and a wrong password both return `invalid_credentials`. A dummy scrypt hash keeps the timing equal (`account.ts:34`). Forgot-password always returns `{ok:true}` (code review).
- **Reset tokens (code review).** 256-bit random, stored hashed, expire after 1 h, and can be used only once (atomic `UPDATE … used_at IS NULL … RETURNING`). Reset links are built from `APP_URL`, not the Host header, so Host-header poisoning does not apply. A reset deletes every session.
- **CSRF.** A POST with no `Origin`, with `Origin: https://evil.example` or with `Origin: null` is rejected with `403`. The only state-changing GET is `/api/v1/unsubscribe`, which requires a 144-bit token (`notification_prefs.unsubscribe_token`). There are no CORS headers anywhere in `src/`.
- **BOLA/IDOR between two students.** B attacked A's objects and every request was refused: conversation GET, PATCH and DELETE (`404`); chat into A's conversation (`404`); regenerate on A's conversation (`400 nothing_to_regenerate`); file GET and DELETE (`404`); plan-task complete and reopen (`404`); suggestion accept and reject (`404`); pending-action confirm (`404`); message feedback (`404`); experience PATCH, DELETE and analyze (`404`). Afterwards psql showed A's data unchanged (title, task state, suggestion state, action state and feedback all the same), and B had written 0 messages into A's conversation.
- **AI tools are scoped to the signed-in user.** In basic-engine chat, B sent "review my cv `<A's file id>`". This triggered `analyze_cv`, which returned `ok:false, not_found`, because `getFileText` runs under B's RLS. The user ID always comes from `ToolContext`, never from model input (`registry.ts`, code review).
- **The pending-action flow works.** The plan tool only creates a `pending_actions` row. A could confirm it (`200`), a second confirm failed (`404`, single-use), and B could not confirm it (`404`). The model has no way to confirm.
- **Tenant isolation between institutions.** Admin C of X did not see D's request to Y in the queue, and approving it by ID returned `404`. `/institution/stats` returned only X. A student got `403` on `/api/v1/admin/users` and `/api/v1/institution/stats`, and the `/admin` page redirected them (`307`). An institution admin got `403` on admin APIs. Every admin route calls `apiUser(["platform_admin"])`, and the page layouts call `requireRole` (grep).
- **RLS is enabled and forced on all user-owned tables.** The app role is not a superuser and does not have `BYPASSRLS`. In psql as the owner without `app.role`, `users` returned 0 rows, so FORCE RLS applies even to the owner. `asUser` checks that the user ID is a UUID, and settings are passed as bound parameters to `set_config`.
- **No SQL injection.** Every `${}` inside SQL interpolates a constant (`COLS`, `SELECT`, `scope`, `MIN_GROUP`, or column names from the fixed `FIELDS` list in `profile.ts`). User input always goes in as `$n` parameters, and `ILIKE` patterns are escaped (code review and grep).
- **XSS and CSP.** The only `dangerouslySetInnerHTML` is the static theme script, which carries the nonce (`layout.tsx:43`). `react-markdown` runs without `rehype-raw`, so it renders no raw HTML, and its default `urlTransform` strips `javascript:` links. Images are not rendered. URLs that come from data are limited to http(s) by `zUrl` or a regex: evidence, proof, `apply_url`, `source_url` and KB `source_url`. Pages are served with CSP `script-src 'self' 'nonce-…' 'strict-dynamic'`, `object-src 'none'`, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff` and `Referrer-Policy`, and the `X-Powered-By` header is absent.
- **File uploads.** The type is decided by magic bytes. HTML/SVG uploaded as `x.pdf` was stored as `text/plain`, an `MZ` executable was rejected (`file_type`), a zip without `word/` was rejected (`file_type`), and 5 MB + 1 byte was rejected (`file_size`). A filename containing a quote and CRLF was cleaned to `x___X-Evil_ 1.pdf`, and no header was injected. Downloads are sent with `content-type: text/plain`, `attachment; filename="…"` (URL-encoded), `nosniff`, `CSP: default-src 'none'; sandbox` and `private, no-store`.
- **Cron endpoint.** A request without a bearer token gets `401`. The comparison is constant-time, and the endpoint stays closed when `CRON_SECRET` is unset.
- **Secrets and errors.** `.env*` is gitignored (except `.env.example`), and env vars are validated with zod. Unexpected errors return only `{code:"internal", message:"Something went wrong", ref}`, with details in the server log. Validation errors return zod issue paths and messages, never stack traces.
- **Logging (code review).** No passwords, tokens or student text are logged; only IDs, sizes and error objects. Email previews, which contain reset links, are logged only when `NODE_ENV` is not `production`. The one exception is the `client.error` passthrough (F-10).
- **LLM guardrails (code review, since no LLM was configured).** The chat loop is limited to 5 rounds and 8 tool calls. History is limited to 16 messages of 6,000 characters each, and tool results are cut at 30k characters. The system prompt is fixed and labels context, tool results and passages as data. Extraction drops quotes that do not appear in the source text. Suggestions need the student's acceptance. No tool can reach the network, and there is no way to send data out through images (images are not rendered and CSP `img-src` is `'self' blob: data:`). Chat is limited to 12 per minute per user (but see F-03).
- **Dependencies.** `npm audit --omit=dev --json` found 0 vulnerabilities across 211 production dependencies (info 0, low 0, moderate 0, high 0, critical 0).
