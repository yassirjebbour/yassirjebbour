# Internationalisation

- Locales: `ar` (Modern Standard Arabic, RTL), `ary` (Moroccan Darija in Arabic script, RTL), `fr`, `en`,
  `zgh` (Standard Moroccan Tamazight in Tifinagh, LTR). Metadata in `src/i18n/config.ts`.
- Catalogues: `src/i18n/messages/{en,fr,ar,ary,zgh}.ts`. `en.ts` is the source; the `Messages` type makes a missing
  key in any locale a build error; `tests/unit/i18n.test.ts` also checks placeholders, plural forms, empty strings and
  that Tamazight uses Tifinagh.
- Plurals: `{ one, other }` (+ `zero, two, few, many` for Arabic and Darija), selected by `Intl.PluralRules`.
- Locale resolution: signed-in user's saved language → `bawsala_locale` cookie → `Accept-Language` (`ar-MA` → Darija)
  → Arabic. Changing language never loses progress (it is stored on the account).
- Numbers use Latin digits in every locale; dates use `Intl.DateTimeFormat`.
- **Professional content** (skill names, roles, resources, knowledge documents) is authored in en/fr/ar; Darija falls
  back to Arabic and Tamazight to French until reviewed translations exist (`pick()` in `config.ts`). The UI shows the
  fallback text rather than inventing translations.
- The assistant answers in the language the student writes (Darija in Arabic script for Arabizi input).
- **Review status:** French and Arabic written by the localisation workstream; Darija and Tamazight written using the
  prototype's dictionary as terminology reference — 69 Tamazight lines marked `// review`. Native-speaker review is a
  launch requirement.
