## 1. Inventory

**Stack:** Next.js 16.4.3 (App Router), React 19.3, TypeScript strict, Tailwind v4 + custom CSS (no shadcn), custom i18n
(no next-intl), PostgreSQL with FORCE row-level security, own auth (password + sessions), Anthropic SDK, local RAG (BM25,
embeddings optional), Vitest + Playwright + axe, npm (not pnpm). CI: `.github/workflows/bawsala-ci.yml` (lint, typecheck,
unit+integration tests, build, Playwright desktop).

**Pages (22):** `/` (homepage, port of the old BAWSALA prototype), `/signin`, `/signup`, `/forgot`, `/reset`, `/help`,
`/privacy`, `/terms`, `/app` (home), `/app/onboarding`, `/app/passport`, `/app/passport/print`, `/app/opportunities`,
`/app/opportunities/[id]`, `/app/plan`, `/app/assistant`, `/app/assistant/[id]`, `/app/profile`, `/app/settings`,
`/app/notifications`, `/institution`, `/admin`.

**API routes (63)** under `/api/v1`: auth (signup, signin, signout, signout-all, forgot, reset), me (export, password,
notification prefs, institution), profile, experiences + analyze, skills + evidence + verify-request, suggestions
accept/reject, passport, opportunities (+ save, target), plan (+ complete/reopen), chat, conversations, messages feedback,
try, search, events, files, notifications, progress, locale, institution (stats, verifications), admin (overview, users,
institutions, opportunities, knowledge, flags, feedback, audit), cron/daily, health.

**Database (4 migrations, 33 tables):** institutions, users, sessions, auth_tokens, rate_limits, profiles, experiences,
skills, user_skills, skill_evidence, skill_suggestions (with `quote`), opportunities, opportunity_skills,
saved_opportunities, plans, plan_tasks, conversations, messages, pending_actions, ai_usage, events, audit_log,
kb_documents, kb_chunks, retrieval_log, notifications, notification_prefs, email_outbox, feature_flags, feedback,
user_files, verification_requests, schema_migrations. Commands: `npm run db:migrate`, `npm run db:seed`, `npm run kb:ingest`.

**AI features:**
- Assistant with 15 tools, streaming, and a basic-engine fallback.
- Skill extraction with a zod schema and quote grounding (`quoteIsGrounded`).
- Cost accounting per attempt, with a platform daily budget.
- Offline reader: `detectSkills()`, the deterministic rules engine used by `/api/v1/try` and the homepage "Try it" box.

**No REBUILD.** The foundations the kit flags as rebuild triggers (no RLS, client-side keys, wrong data model) are all
sound. The data model maps onto the kit's names without new tables: stories → `experiences`, skills_found →
`skill_suggestions` + `user_skills`, ai_runs → `ai_usage`, events → `events`. Renaming tables would cost more than it
returns. Recommended: keep the tables and document the mapping in `docs/DECISIONS.md`.
